Captain’s Chair

A command layer for one operator’s AI capability. It is powerful enough to build, research, run a firm, and manage life, yet disciplined enough to turn client work into accepted, evidence-backed outcomes.

The answer first

The Chair is a control plane, not another AI persona

Claude Code remains the primary working harness. The Chair supplies the durable run identity, knowledge, memory, routing, budgets, policy, evidence, evaluation, and effect controls that a harness cannot provide by itself. Other AI lanes remain native, but their work ties back through a shared packet and event record.

The winning architecture is a One locally deployed authority with internal modules and stable external contracts. It avoids a microservice fleet while preserving replaceable seams.. Its defining rule is simple: models may propose; deterministic code alone changes authoritative state or causes an external effect.

Workspace Operator-sovereign work

Research, prototyping, personal administration, creative work, and direct building stay fluid. The Chair records and assists; it does not turn the operator’s foreground commands into a permission maze.

  • Exploration may remain incomplete or provisional.
  • Direct commands can authorize narrowly scoped effects.
  • Useful results and learning can enter durable memory.

Governed Client-delivery function

Client work crosses a harder boundary. Engagement rules, isolated workers, quality contracts, exact-byte acceptance, delivery controls, and replay evidence determine what can be called a finished outcome.

  • Automated checks must be able to fail.
  • A named human accepts the actual artifact digest.
  • Delivery needs an attributable receipt or stays unknown.
Core invariant. The dashboard never says “done” because an agent said so. It derives status from artifact digests, process results, policy decisions, receipts, and human acceptance.

System shape

One control plane, many native work surfaces

The operator may start in Claude Code, another coding harness, an executive-assistant lane, a notebook, or a local model. Those surfaces do not become peers competing for authority. They submit work and observations to the kernel, which owns the managed record.

Why the architecture stays local first

The initial system needs three process shapes: cc-kernel, the short-lived cc client and hooks, and isolated cc-worker jobs. SQLite holds transactional state and the outbox. Immutable files hold evidence. macOS Keychain holds secrets. The loopback dashboard is a projection, not another control authority.

This is deliberately smaller than a durable workflow service or federated agent mesh. Stable ports preserve the option to substitute PostgreSQL, Temporal, remote workers, or object storage when measured concurrency or recovery needs justify them.

How work moves

Three loops share one evidence spine

The loops differ in finish line, not in basic mechanics. Each begins with a A versioned envelope for intent, initiator, mode, data class, input evidence, requested outputs, budget, and source lane.. It retrieves bounded context, routes capabilities, records costs and observations, and retains learning. Use the tabs to compare them.

Everyday: from question to retained learning

A task can stay local, use one model, span several AI lanes, or propose a business-system action. It finishes when the requested result exists and its required observations validate. A convincing conversation is not completion evidence.

Governed delivery: accepted bytes are the finish line

A client run is engagement-bound from intake. It uses isolated workers, a quality contract that can fail, a controlled Artifact Factory, exact-byte human acceptance, and a brokered delivery receipt.

Cross-lane handoff without transcript dumping

A handoff exports the task intent, current state, unresolved questions, decisions, selected context references, artifact and revision IDs, remaining budget, active grants, next expected step, and capture-coverage statement. The receiving lane either continues the run or forks a child. If it exits without returning a result, the run becomes lane_unconfirmed, not complete.

The mechanical proof predicate 
proven(run, workflow) =
  real_input
  AND accepted_digest = delivered_digest
  AND named_human_acceptance
  AND all_required_gates_pass
  AND claimed_capabilities ⊆ observed_successful_capabilities
  AND cost_reconciled
  AND human_edit_effort_recorded
  AND exceptions_closed_or_authorized
  AND replay_bundle_valid

An authorized exception names the failed predicate, reason, ratifier, scope, and expiry. It does not erase the failure. A rejected run ends; revision begins a linked child run.

Never silent

Governance controls system reach, not operator curiosity

The Chair does not use a blanket human checkpoint. It inspects the action about to happen: who initiated it, where it reaches, what data crosses a boundary, whether it can be reversed, what it costs, and whether an explicit grant covers it.

The The only managed component allowed to resolve system-issued credentials and execute external actions after policy, authority, and budget checks. is the hard boundary

Why hooks are not enough

Claude Code hooks add interception and evidence at tool boundaries, but matching logic is not the only security control. Governed workers lack connector credentials and unrestricted egress. The Effect Broker alone can exchange a kernel-signed action token for credentials and an external call. That credential and network boundary turns policy from advice into enforcement.

Compounding context

Knowledge is curated; memory is promoted; indexes are disposable

The Chair avoids treating one embedding store as both truth and memory. It separates immutable source bytes, versioned claims, durable memories, and rebuildable retrieval indexes.

Source objects

Original bytes plus origin, time, license, digest, data class, engagement, and parser version. These are immutable evidence.

Curated claims

Small assertions linked to source spans. Claims can be proposed, active, contested, superseded, or withdrawn.

Derived indexes

Chunks, embeddings, terms, entity links, and ranking features. Every index can be rebuilt from the first two layers.

Memory has types and promotion rules

Models write candidates, not canonical memory. Low-risk operational measurements may promote under a standing rule. Preferences, significant decisions, client facts, contested claims, and governance changes require a human promotion path.

Episodic · what happenedSemantic · what is knownProcedural · how work is doneWorking state · what resumes next
How retrieval quality becomes measurable

Engagement and data-class filters run before semantic retrieval and again before serialization. Hybrid retrieval combines lexical, vector, and explicit-link signals. Every context pack carries source spans, conflict status, exclusions, and a token budget.

Quality uses labeled queries, Recall@k, MRR, nDCG@k, citation coverage, citation correctness, answer faithfulness, zero-tolerance cross-engagement canaries, and real miss feedback. Model-based RAG scores are trend signals; human-labeled cases anchor release decisions.

Architecture decision

Why the local kernel won

The candidates were scored against the binding product contract, not generic platform fashion. The local kernel wins on control, proof, bounded cost, and sustainable operating burden. The workflow platform wins on large-scale durable execution; the mesh wins on lane independence.

Local kernel480
Workflow platform386
Federated mesh310

The winner borrows, but does not blend

From durable workflows: persisted step state, retries, timers, cancellation, idempotency, and human signals. From the mesh: capability advertisement and portable work packets. The kernel still remains the sole managed authority.

Scale trigger: replace adapters only when write contention, remote-worker demand, or recovery targets prove the local deployment insufficient.

Capability before calendar

Build the whole shape thinly, then deepen it

The first build must prove a real governed run end to end. Component completion is not proof. Later phases expand the same contracts without redesigning the control model.

Governed tracer bullet

One real low-risk request, one curated source, one Claude route, one quality contract that fails and passes, exact-byte acceptance, one controlled external delivery, receipt, cost, edit effort, and replay bundle.

Adversarial design

Top failures and the containment move

The design assumes models overclaim, APIs time out ambiguously, indexes regress, humans tire, and local machinery can fail. Filter the list by failure family.

AuthorityAgent bypasses the Effect Broker

Governed workers lack connector credentials and unrestricted egress. Hooks add interception; the credential and network boundary supplies enforcement.

EvidenceAgent says “done” without proof

The state projector ignores prose. Missing artifacts, tests, acceptance, or receipts leave the run running, failed, rejected, or unknown.

AuthorityClient data crosses an unapproved boundary

Hard filters and policy block before the model call. Discovered crossing becomes an incident, not a warning buried in a transcript.

OperationsExternal call succeeds but times out locally

Use idempotency and destination read-back. Without either, stop at outcome_unknown; never retry by guess.

OperationsRetry storm consumes money

Hierarchical reservations, bounded retries, circuit breakers, and failure-class rules prevent a loop from minting budget.

EvidenceLedger corrupts or projections diverge

Verify SQLite, event hashes, signed checkpoints, and scratch replay. Pause effects until authority is restored.

KnowledgeRetrieval misses decisive context

Golden-query regressions and human miss feedback fail the relevant gate; changes require a labeled test, not intuition.

KnowledgeMemory becomes stale or self-reinforcing

Models write candidates. Active semantic memory needs provenance and promotion; corrections supersede rather than overwrite history.

HumanRubber-stamping under decision fatigue

Batch low-risk items. Show exact target, digest, delta, and consequence. Separate unusually broad grants without obstructing direct authority.

EvidenceAccepted bytes differ from delivered bytes

The broker accepts only the release-manifest digest. Any post-acceptance byte change invalidates evaluation and acceptance.

OperationsModel alias changes behavior or price

Governed routes pin a concrete version and price snapshot. Unknown versions enter evaluation, not production.

HumanArchitecture accumulates machinery

Every component needs a requirement, measured gap, buy/build comparison, removal plan, and proof target. The three-process deployment remains the default.
